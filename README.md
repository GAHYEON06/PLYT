# PLYT — 좋은 시간은, 이어지니까

공간 예약의 희망 시간을 요청하고, 기존 예약자에게 일정 이동을 제안한 뒤, 양측의 수락과 운영자의 확인을 기록하는 앱·웹 개발판입니다. 웹과 안드로이드 앱이 같은 C++ REST API와 SQLite 데이터베이스를 사용합니다. 브라우저에만 요청을 저장하던 기존 `index.html`에서 서버 저장 구조로 확장했습니다.

현재 공간 3곳, 설명, 가격은 시연용 예시입니다. 입점 계약이나 실제 가용 시간표를 뜻하지 않습니다. 결제, 문자·푸시 발송, 네이버 예약·캐치테이블 연동, 보상 송금은 연결하지 않았습니다. 운영자의 수동 확인 기록과 실제 외부 예약 시스템의 처리는 구분해야 합니다.

## 구성

| 경로 | 내용 |
|---|---|
| `server/main.cpp` | C++17 HTTP 서버, 인증, 권한 검사, 요청·제안·수락·확정, 변경 이력 |
| `server/vendor/` | cpp-httplib 0.18.3, nlohmann/json 3.11.3, SQLite 3.50.4 소스 |
| `web/` | 반응형 웹 화면과 API 클라이언트 |
| `android/` | Android Studio에서 여는 Kotlin 네이티브 앱 프로젝트 |
| `build/plyt-server.exe` | Windows C++ 서버 빌드 결과 — 소스에서 빌드 후 생성 |
| `downloads/PLYT-debug.apk` | 빌드 검증을 마친 안드로이드 개발용 설치 파일 |
| `data/` | 첫 서버 실행 시 생성되는 데이터베이스와 운영자 등록 코드. Git에 제외 |
| `Dockerfile`, `CMakeLists.txt` | Linux 컨테이너와 CMake 빌드 구성 |

웹 화면은 브라우저가 표시하는 HTML·CSS·JavaScript를 사용합니다. 인증과 데이터 저장, 예약 상태 변경은 C++ 서버가 수행합니다. C++로 화면 마크업을 대체하는 방식은 아닙니다. 안드로이드 앱은 웹뷰를 감싸는 앱이 아닌 Kotlin 화면입니다.

## Windows에서 실행

가장 간단한 방법은 `start-server.cmd`를 더블클릭한 뒤 브라우저에서 아래 로컬 주소를 여는 것입니다. PowerShell에서는 이 폴더로 이동한 뒤 실행합니다.

```powershell
.\start-server.ps1
```

브라우저에서 [로컬 PLYT 웹](http://127.0.0.1:8080)을 엽니다. 이 주소는 서버를 켠 컴퓨터에서 접속하는 주소입니다. 다른 사람에게 공개된 인터넷 주소가 아닙니다. 앱·웹을 사용하는 동안 서버를 실행한 터미널을 유지합니다. 종료는 `Ctrl+C`입니다.

포트를 바꾸려면 ` .\start-server.ps1 -Port 8081`을 사용합니다. 기본적으로 `127.0.0.1`에서만 수신하므로 외부 네트워크에 바로 노출되지 않습니다.

C++ 소스를 수정한 뒤에는 다음으로 다시 빌드합니다. `build-server.ps1`은 이 컴퓨터에 있는 Visual Studio C++ 도구 경로를 사용합니다. 다른 컴퓨터에서는 해당 파일의 `vcvars64.bat` 경로를 맞추거나 CMake를 사용합니다.

```powershell
.\build-server.ps1
```

## 계정과 예약 흐름

고정된 공용 비밀번호는 없습니다. 웹이나 앱의 회원가입으로 사용할 계정을 생성합니다. 비밀번호는 8자 이상이며 서버에는 무작위 salt와 PBKDF2-HMAC-SHA256 파생 값이 저장됩니다. 인증 토큰의 유효기간은 7일입니다. 로그아웃하면 서버 토큰이 폐기됩니다.

1. 일반 고객 B와 기존 예약자 A가 각자 가입합니다. 기능을 확인할 때는 브라우저 프로필을 나누거나 앱과 브라우저를 사용합니다.
2. 사장님 계정을 처음 만들 때 서버 컴퓨터의 `data/owner-setup-key.txt`에 있는 등록 코드를 사장님 회원가입의 코드 칸에 입력합니다. 이 파일의 코드를 저장소에 올리거나 다른 사람에게 공유하지 않습니다. 현재는 운영자 계정 1개를 갖는 단일 운영 조직용 개발판입니다.
3. B가 공간, 희망 날짜·시간, 이용시간, 추가 부담 한도를 정해 요청합니다. 이것만으로 예약이 확정되지 않습니다.
4. 사장님이 실제 기존 예약을 확인하고 A의 가입 이메일, 원래 예약의 확인 번호, 대체 날짜·시간, 보상 조건을 입력해 제안합니다.
5. A가 제안을 수락한 다음 B가 보상 조건을 확인하고 수락합니다. 제안은 생성 후 48시간의 응답 기한을 갖습니다.
6. 사장님이 외부 예약 시스템에서 필요한 변경을 직접 처리한 다음, 반영 확인과 확인 번호를 기록합니다. PLYT는 수동 확인 결과를 기록합니다. 외부 시스템을 자동 변경하지 않습니다.
7. 결제 미연동과 보상 미지급 상태는 계속 구분해 표시합니다. 운영자 확인이 결제·송금 완료를 뜻하지 않습니다.

요청은 `pending → proposed → accepted_a → accepted_b → confirmed` 순서로 진행합니다. 확정 전 요청자는 취소할 수 있고, 제안 당사자는 응답 단계에서 거절할 수 있습니다. 이미 확정된 요청을 취소·환불하는 운영 흐름은 후속 구현 범위입니다.

현재 입력 가능한 운영시간은 09:00–22:00이며, 시작 시간은 30분 단위, 이용시간은 1–4시간입니다. 서버의 날짜·시간 해석은 서버 시간대를 따릅니다. 한국 서비스 운영 환경은 `Asia/Seoul`로 맞춥니다. Dockerfile에는 해당 시간대를 설정했습니다.

## Android Studio

Android Studio에서 `android` 폴더를 프로젝트로 엽니다. SDK 경로는 각 컴퓨터의 `android/local.properties`에 설정합니다. 이 컴퓨터의 SDK는 `C:\AndroidStudioSDK`입니다.

앱의 서버 주소는 설정 화면에서 변경할 수 있습니다. 에뮬레이터에서 호스트 컴퓨터에 접근하는 기본 주소는 `http://10.0.2.2:8080`입니다. USB 또는 에뮬레이터의 포트 역방향 전달을 사용하면 다음과 같이 연결할 수 있습니다.

```powershell
C:\AndroidStudioSDK\platform-tools\adb.exe reverse tcp:8080 tcp:8080
```

이 경우 앱 서버 주소를 `http://127.0.0.1:8080`으로 지정합니다. `adb reverse`는 연결된 개발 기기에서만 유효합니다. 실기기에서 외부 인터넷으로 사용하는 앱에는 실제 HTTPS 서버 주소가 필요합니다. 개발용 HTTP 허용 설정은 디버그 빌드에만 적용합니다.

## Linux/Docker 배포 준비

Docker가 있는 환경에서 다음으로 빌드하고 실행할 수 있습니다. 컨테이너 빌드 및 실제 외부 호스팅은 별도의 환경 검증이 필요합니다.

```sh
docker build -t plyt .
docker volume create plyt-data
docker run --name plyt --restart unless-stopped -p 127.0.0.1:8080:8080 -v plyt-data:/app/data plyt
```

컨테이너 안의 `/app/data`에 지속 저장소를 연결해야 재배포·재시작 후 계정과 요청을 보존할 수 있습니다. 웹 파일과 C++ API를 같은 도메인에서 제공하고, 앞단의 HTTPS 프록시가 인증서를 관리하는 구성을 권장합니다. 개발 기본 설정은 HTTP이므로 인터넷 운영 시 TLS 구성을 완료해야 합니다.

CMake만 사용할 때는 C/C++17 컴파일러, CMake 3.20 이상, OpenSSL 개발 라이브러리가 필요합니다.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 2
./build/plyt-server .
```

## GitHub와 공개 배포 상태

기준 저장소는 [GAHYEON06/PLYT](https://github.com/GAHYEON06/PLYT)입니다. 제공받은 원본 저장소에는 `index.html`만 있었습니다. 이 저장소에는 C++ 서버, 반응형 웹, Android Studio 프로젝트와 검증 결과를 함께 제공합니다. 루트 `index.html`은 기존 데모를 보존한 파일이며, 새 서비스의 웹 화면은 `web/`입니다. C++ 서버가 `web/`과 `/api`를 함께 제공합니다. 코드 업로드와 공개 서비스 배포는 별개이며, 공개 운영 배포는 아직 수행하지 않았습니다.

일반 정적 웹 호스팅에 `index.html`만 올려서는 이 C++ 서버가 실행되지 않습니다. 공개 서비스를 열려면 C++ 프로세스 실행, 지속 저장소, HTTPS를 제공하는 배포 대상을 정한 뒤 해당 환경에서 빌드·운영 검증을 해야 합니다. 별도의 프런트엔드 호스트를 쓰려면 동일 도메인의 `/api`가 C++ 서버로 연결되도록 라우팅을 구성해야 합니다.

## 검증 범위와 다음 개발

Windows 네이티브 C++ 서버에서 65개 API·상태 검증과 3개 재시작 저장 검증, 총 68개 항목을 통과했습니다. 인증, 권한 분리, 즐겨찾기 저장·삭제, 요청 중복, 일정과 보상 한도, 양측 수락 순서, 운영자 수동 확인, 시간 충돌 차단, 취소, 로그아웃과 변경 이력을 확인했습니다. 서버를 재시작한 뒤 세션·확정 요청·즐겨찾기가 유지되는 것도 확인했습니다. Android 빌드와 화면 검증은 최종 작업 결과의 실제 확인 범위를 기준으로 봅니다. Linux 컨테이너 빌드는 실행하지 않았습니다. 테스트 계정과 API 테스트 데이터는 배포용 `data/`에 포함하지 않습니다.

현재는 실제 데이터를 저장하고 계정별로 확인하는 동작 검증용 개발판입니다. 다수 업체가 가입하는 서비스로 운영하기 전에는 업체·룸별 권한과 실제 가용 시간표 관리, 이메일 확인·비밀번호 재설정, 운영 모니터링과 백업 복구, 개인정보 처리 안내, 알림 발송, 결제·정산 계약 및 외부 예약 연동을 구현하고 검증해야 합니다. 공간 이름과 가격도 실제 입점 데이터로 교체해야 합니다.
